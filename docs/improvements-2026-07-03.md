## Technical

### 1. Guard block-map access in the social-image route
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `pages/api/social-image.tsx` does `const keys = Object.keys(recordMap?.block || {})` then `getBlockValue(recordMap?.block?.[keys[0]!])` with a non-null assertion. If the record map has no blocks, `keys[0]` is `undefined` and the `!` hides it — under `noUncheckedIndexedAccess` this is exactly the unsound access the flag targets, and it can crash the edge route.
- **Proposal.** Pull `const firstBlockId = Object.keys(recordMap?.block ?? {})[0]` and `if (!firstBlockId) return`/throw a clear error before indexing. Same treatment for the `notion_user` first-key access.
- **Risks / trade-offs.** None — strengthens an existing throw path.
- **Files.** `pages/api/social-image.tsx`

### 2. Validate before the non-null assertion in `get-site-map`
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `lib/get-site-map.ts` casts `getCanonicalPageId(pageId, recordMap, { uuid })!` to non-null. If it returns `undefined`, the `!` silently produces an `undefined` key in the canonical map, corrupting the generated sitemap/index at build with no error.
- **Proposal.** Assign to a variable, and `if (!canonicalPageId) { console.warn(...); continue }` (skip the page) or throw with the offending `pageId`. Makes a bad crawl explicit instead of shipping a corrupt index.
- **Risks / trade-offs.** Turning silent skips into throws could fail a build on a genuinely-unresolvable page; a warn-and-skip keeps builds resilient.
- **Files.** `lib/get-site-map.ts`

### 3. Add integration tests for the Notion cache + retry behavior
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** The recently-unified caching (`lib/notion.ts` pMemoize + ExpiryMap) and the retry client (`lib/notion-api.ts`) are correctness-critical and untested. The Vitest suite only covers `cn`, `getErrorMessage`, and `normalizePageIdPath`.
- **Proposal.** With `vi.useFakeTimers()`, test: concurrent `getPage` calls share one promise (in-flight dedup), ExpiryMap evicts after TTL, rejected fetches are not cached, and the retry client honors max-retries on 429/5xx. Mock `notion`/`buildNotion`.
- **Risks / trade-offs.** Requires mocking notion-client; fake timers + promises need care to avoid flakiness.
- **Files.** `lib/__tests__/notion-caching.test.ts` (new), `vitest.config.ts`

### 4. Type the RecordMap property extensions
- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `lib/notion.ts` attaches preview images via `(recordMap as any).preview_images`, and `lib/acl.ts` iterates `Object.keys(recordMap.block)` with indexed access. These are the remaining `any`/loose spots left after the strictness pass.
- **Proposal.** Add an `ExtendedPreviewRecordMap` (mirroring the existing `ExtendedTweetRecordMap`) in `lib/types.ts` for `preview_images`; in `acl.ts` iterate `Object.entries(recordMap.block)` to avoid indexed access.
- **Risks / trade-offs.** May surface a few more spots relying on the loose shape.
- **Files.** `lib/types.ts`, `lib/notion.ts`, `lib/acl.ts`

### 5. Type the NotionRenderer property-override callbacks
- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `components/NotionPage.tsx` defines `propertyLastEditedTimeValue`, `propertyDateValue`, `propertyTextValue` with `({ block, pageHeader }: any, …)`. These are the `any`s intentionally deferred in the last strictness pass because they're coupled to react-notion-x's override contract.
- **Proposal.** Adopt the property-value handler types exported by react-notion-x (or a locally-declared minimal interface matching `{ block, data, schema, pageHeader }`) so a react-notion-x API change surfaces at compile time.
- **Risks / trade-offs.** react-notion-x's exported types may be incomplete, needing a narrow local type instead.
- **Files.** `components/NotionPage.tsx`

### 6. Persist the preview-image LQIP cache to disk to speed builds
- **Impact:** 🟡 med · **Effort:** M · **Status:** ✅ accepted
- **Problem.** `site.config.ts` sets `isPreviewImageSupportEnabled: true`, but with Redis disabled `lib/db.ts` returns a plain in-memory `new Keyv()`. So every `next build` re-fetches each image (`ky`) and re-runs `lqip()` from scratch — the in-memory cache resets per process, making image-heavy builds slow.
- **Proposal.** Back the Keyv cache with a committed on-disk store (a file-backed Keyv adapter, or write the LQIP map to `lib/generated/preview-images.json` during prebuild and read it in `getPreviewImageMap`). Keeps LQIP quality without paying the fetch+process cost every build.
- **Risks / trade-offs.** A committed cache can go stale when images change; key on the image URL and regenerate on miss. Adds a generated artifact to keep in sync.
- **Files.** `lib/preview-images.ts`, `lib/db.ts`, `notion-index.config.ts`

### 7. Distinguish cache misses from cache errors
- **Impact:** 🟡 med · **Effort:** M · **Status:** ✅ accepted
- **Problem.** `lib/preview-images.ts` and `lib/get-tweets.ts` both `catch` a failed `db.get()`, log, and fall through — a Redis/network error is indistinguishable from a genuine miss, so a flaky cache silently triggers full regeneration every time.
- **Proposal.** Return a small result type from the cache read (`{ ok, value }`); only treat `null`/`undefined` as a miss when `ok`. On error, skip the write-back (don't overwrite a possibly-good remote value) and emit a distinct warning.
- **Risks / trade-offs.** Adds a little plumbing to `lib/db.ts` callers; low behavioral risk.
- **Files.** `lib/preview-images.ts`, `lib/get-tweets.ts`, `lib/db.ts`

## UI/UX & Design

### 8. Give the keyboard cursor its own state, distinct from selection
- **Impact:** 🔴 high · **Effort:** M · **Status:** ❌ rejected
- **Problem.** The canvas supports arrow-key navigation with a `cursorLensId` (`LensesPage.tsx`), but when the panel is closed there's no visual state distinguishing the cursor card from its neighbors — a keyboard user can't see where they are. When the panel is open, `.cardSelected` shows a neutral ring (`rgba(30,26,20,0.85)`) that nearly disappears on light-colored cards, and hovering a sibling can't "preview" without dismissing the panel. Two competing concerns (navigation cursor vs. selection intent) share one visual treatment.
- **Proposal.** Add a `.cardCursor` state (subtle accent-colored dashed/gradient outline, not a full ring) for `cursorLensId` when no panel is open, plus `aria-current="true"`. Make `.cardSelected`'s ring adapt via `color-mix` so it reads on any card background. Keep hover-preview independent of selection.
- **Risks / trade-offs.** More visual states to maintain; tune opacity so the cursor outline doesn't compete with the selection ring.
- **Files.** `components/wustep/lenses/LensesPage.tsx`, `components/wustep/lenses/cards.tsx`, `components/wustep/lenses/LensesPage.module.css`

### 9. Honor `prefers-reduced-motion` in the Prompting demos
- **Impact:** 🔴 high · **Effort:** M · **Status:** ❌ rejected
- **Problem.** `EquationDemo` and `PromptInputDemo` reference reduced-motion, but `TreeDemo.tsx` (which has an auto-advancing `touring` animation) and `ColleagueDemo.tsx` (animated share state) do not — so a motion-sensitive visitor gets unrequested movement on the Prompting guide. The project targets WCAG 2.2 AA with a motion-reduced experience.
- **Proposal.** Gate the `TreeDemo` tour loop and `ColleagueDemo` transitions on the existing `usefPrefersReducedMotion` hook (`lib/use-prefers-reduced-motion.ts`): pause auto-tour and swap transitions for instant state changes when reduced motion is requested.
- **Risks / trade-offs.** The demos lose some of their "wow" for those users — but that's the point; keep the end state fully legible without motion.
- **Files.** `components/wustep/prompting/TreeDemo.tsx`, `components/wustep/prompting/ColleagueDemo.tsx`

### 10. Reflow the Lenses center card on small viewports
- **Impact:** 🟡 med · **Effort:** M · **Status:** ✅ accepted
- **Problem.** The deck is responsive (container queries, clamps at 600/1000/1440px), but the focal "Lenses" center card keeps its `grid-column: 4 / 6; grid-row: 2 / 4` 2×2 span below 600px, where the grid collapses — its padding doesn't scale and the title/tagline sit at their clamp floor, so it reads awkwardly on phones.
- **Proposal.** Add a `@container deck (max-width: 599px)` rule making the center card span full width as a short hero (illustration left, text right, fixed ~180px height). Improves thumb-scroll legibility while keeping it the "explain the deck" entry point.
- **Risks / trade-offs.** Hero composition must hold across the palette; verify contrast on dark cards and at 320px.
- **Files.** `components/wustep/lenses/LensesPage.module.css`

### 11. Unify the motion vocabulary across loading and error states
- **Impact:** 🟡 med · **Effort:** M · **Status:** ✅ accepted
- **Problem.** Three motion dialects coexist: the Lenses deck uses exponential/spring easing (`--ease-out-quint`, `--ease-spring-soft`, 600–700ms), the error page staggers at 200–600ms, and the loading spinner is `0.6s linear infinite` (mechanical). Surfaces don't feel from one family — an interface-craft consistency gap.
- **Proposal.** Promote the Lenses easing tokens to shared vars and apply them: swap the spinner's `linear` for `--ease-out-expo`/a dampened spring, align the error-page stagger to the ~420ms interaction curve. All gated on `prefers-reduced-motion`.
- **Risks / trade-offs.** Broad touch across CSS; must preserve reduced-motion behavior everywhere.
- **Files.** `components/Page404.module.css`, `components/styles.module.css`, `components/LoadingIcon.tsx`, `styles/globals.css`

### 12. Add a chapter-position indicator to the Prompting guide
- **Impact:** 🟡 med · **Effort:** M · **Status:** ❌ rejected
- **Problem.** `PromptingLayout.tsx` wraps 9+ chapters with a ToC popover and prev/next `ChapterNav`, but nothing communicates *where you are* in the guide or how much remains — an interface-craft expectation-setting miss for a long linear read.
- **Proposal.** Add a compact "Chapter N of M" mark and/or a thin progress rule in the running head (it already renders `chapter.mark`). Reinforces momentum and scope without adding noise.
- **Risks / trade-offs.** Keep it quiet so it doesn't compete with the editorial "manual" aesthetic.
- **Files.** `components/wustep/prompting/PromptingLayout.tsx`, `components/wustep/prompting/PromptingPage.module.css`

### 13. Confirm the keyboard-scroll target landed
- **Impact:** 🟡 med · **Effort:** M · **Status:** ❌ rejected
- **Problem.** Arrow-key navigation calls `scrollIntoView({ behavior: 'smooth', inline: 'nearest' })` (`LensesPage.tsx`). On a tall or horizontally-scrolling deck the card just appears with no confirmation it's the new target, and `inline: 'nearest'` can leave it at the viewport edge where the focus tagline is cramped.
- **Proposal.** Briefly pulse the target card's accent outline (~300ms) after the scroll settles, and use `inline: 'center'` below 1000px so the card lands centered with room for its tagline.
- **Risks / trade-offs.** A mistimed pulse can feel janky; keep it short and gentle, and skip under reduced motion.
- **Files.** `components/wustep/lenses/LensesPage.tsx`, `components/wustep/lenses/LensesPage.module.css`

### 14. Add a "copy link" affordance to the lens panel
- **Impact:** ⚪ low · **Effort:** S · **Status:** ❌ rejected
- **Problem.** Lenses already have shareable URLs (`/lenses/<id>`, synced via `history.replaceState` in `LensesPage.tsx`), but there's no UI to grab one — a user has to read it from the address bar. The sharing infrastructure exists; the affordance is missing.
- **Proposal.** Add a "Copy link" button in `.panelControls` next to the close button that copies `${origin}/lenses/${lens.id}` and shows a 2s "Copied!" confirmation, styled like the existing 40px control, with `aria-label` and a clipboard fallback.
- **Risks / trade-offs.** Clipboard API is unavailable in some contexts — include a select-fallback.
- **Files.** `components/wustep/lenses/SidePanel.tsx`, `components/wustep/lenses/LensesPage.module.css`

## DevEx

### 15. Cache the pnpm store in CI
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `.github/workflows/build.yml` runs `pnpm install --frozen-lockfile` with no store caching, so every push re-downloads all dependencies — wasted minutes on every run.
- **Proposal.** Cache the pnpm store between runs (mise-action can cache, or add `actions/cache` keyed on `pnpm-lock.yaml` + a `pnpm store path` step). Cuts install to seconds on a hit; frozen lockfile keeps it deterministic.
- **Risks / trade-offs.** None material; a stale cache key just misses and rebuilds.
- **Files.** `.github/workflows/build.yml`

### 16. Expand unit coverage for URL/ACL logic and turn on coverage reporting
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** Routing- and access-critical code — `lib/get-canonical-page-id.ts`, `lib/map-page-url.ts`, `lib/acl.ts` — has zero tests, and Vitest has no coverage reporting configured.
- **Proposal.** Add `@vitest/coverage-v8`, enable coverage in `vitest.config.ts`, and write tests for `getCanonicalPageId` (override/addition/fallback), `mapPageUrl` (root + nested), and `pageAcl` (workspace mismatch). Establish a rough `lib/` baseline.
- **Risks / trade-offs.** Tests must mock notion-utils inputs; may surface existing edge-case bugs (a feature).
- **Files.** `lib/__tests__/get-canonical-page-id.test.ts`, `lib/__tests__/map-page-url.test.ts`, `lib/__tests__/acl.test.ts` (new), `vitest.config.ts`, `package.json`

### 17. Automate dependency updates (Dependabot or Renovate)
- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** 100+ deps in `pnpm-lock.yaml` and no update automation — security patches and minor bumps rely on manual `pnpm up`, easy to defer for months on a solo project.
- **Proposal.** Add `.github/dependabot.yml` (or `renovate.json`): weekly checks, grouped/batched PRs, auto-merge patch/minor when CI passes, manual review for majors.
- **Risks / trade-offs.** Auto-merged minors can hide subtle breaks — gated on the (now build+test) CI passing.
- **Files.** `.github/dependabot.yml` or `renovate.json` (new)

### 18. Validate environment variables at startup with a schema
- **Impact:** 🟡 med · **Effort:** M · **Status:** ✅ accepted
- **Problem.** `lib/config.ts` reads optional env vars (`OWNER_MODE_SECRET`, `TWITTER_ACCESS_TOKEN`, `REDIS_*`) with no validation, so a typo or wrong type slips silently to runtime. (`.env.local` is correctly gitignored — no committed secret.)
- **Proposal.** Add a small schema validation (zod, or a hand-rolled check to avoid a new dep) run once in `lib/config.ts`, throwing a clear message on malformed required vars. Document the full env surface + failure modes in `docs/configuration.md`.
- **Risks / trade-offs.** Over-strict rules could break a valid deploy — validate shape, not presence, for optional vars.
- **Files.** `lib/config.ts` (or new `lib/validate-env.ts`), `docs/configuration.md`, `.env.example`

### 19. Document git hooks and add a CI drift-check for generated artifacts
- **Impact:** 🟡 med · **Effort:** M · **Status:** ✅ accepted
- **Problem.** `contributing.md` doesn't mention the `simple-git-hooks` pre-commit/pre-push hooks or the `lint-staged` `sync-lenses` step, so contributors may `--no-verify` unknowingly. And the committed generated artifacts (`lib/generated/notion-index.json`, `components/wustep/lenses/lenses.json`, `public/sitemap.xml`) aren't verified fresh in CI.
- **Proposal.** Document the hooks in `contributing.md`; add a CI step that runs `pnpm lenses:sync` and fails if `lenses.json` differs from the committed copy (`git diff --exit-code`).
- **Risks / trade-offs.** Adds a couple CI seconds; a schema change requires a local re-sync (intended).
- **Files.** `contributing.md`, `.github/workflows/build.yml`

### 20. Unit-test the `sync-lenses` script
- **Impact:** 🟡 med · **Effort:** M · **Status:** ✅ accepted
- **Problem.** `scripts/sync-lenses.mjs` validates required fields + unique ids but nothing tests its output schema, so a malformed `lenses.md` entry could still emit valid-but-broken JSON that reaches `main`.
- **Proposal.** Add a test that runs the sync over a fixture `lenses.md` with valid + invalid entries and asserts the JSON shape (id/category/title/tagline/bg/fg/illustration/body present) and that bad entries are rejected with clear errors.
- **Risks / trade-offs.** Another test + fixture to maintain in step with the schema.
- **Files.** `scripts/__tests__/sync-lenses.test.ts` (new), `vitest.config.ts`
