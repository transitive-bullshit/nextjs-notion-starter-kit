## Technical

### 1. Remove debug `console.log` statements from production paths
- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** Debug logs remain in runtime/build paths: `lib/resolve-notion-page.ts` logs the `site` object, `lib/get-site-map.ts` logs every page fetch, `lib/preview-images.ts` logs LQIP metadata, `pages/[pageId].tsx` logs all static paths, and `pages/api/search-notion.ts` logs search params + results. These bloat server logs and can leak internal shapes.
- **Proposal.** Remove them, or guard behind an `isDev` check. Keep `console.warn` only for genuine warnings (retries, ACL rejections). Verify each site individually rather than a blanket delete.
- **Risks / trade-offs.** Loses some ad-hoc debugging signal; a couple may be intentional build diagnostics — review before removing.
- **Files.** `lib/resolve-notion-page.ts`, `lib/get-site-map.ts`, `lib/preview-images.ts`, `pages/[pageId].tsx`, `pages/api/search-notion.ts`

### 2. Consolidate triple analytics (Fathom + PostHog + Google Analytics)
- **Impact:** 🟡 med · **Effort:** M · **Status:** ✅ accepted
- **Problem.** `pages/_app.tsx` initializes three analytics systems sending overlapping pageviews, each with its own opt-out and network cost. `lib/config.ts` exports `fathomId`, `posthogId`, `googleId`. For a personal site this is redundant client weight + three third-party requests. (`react-ga` is also declared in `package.json`.)
- **Proposal.** Pick one provider (PostHog for event flexibility, or Fathom for privacy/simplicity), remove the other two from `SiteAnalytics()` and their config exports + env plumbing. Drop `react-ga` from deps if the GA path goes.
- **Risks / trade-offs.** Loses continuity with historical data in the dropped tools; owner-mode skip logic must still fire for the chosen provider. This is a judgment call — you may want to keep more than one.
- **Files.** `pages/_app.tsx`, `lib/config.ts`, `package.json`, `.env.example`

### 3. Unify the three caching strategies in the Notion layer
- **Impact:** 🟡 med · **Effort:** M · **Status:** ✅ accepted
- **Problem.** Three coexisting cache mechanisms: a hand-rolled `createTTLCache()` in `lib/notion.ts` (manual expiry Map) for `pageCache`/`searchCache`, `pMemoize` on `getNavigationLinkPages()` in the same file, and `pMemoize` + `ExpiryMap` in `lib/search-notion.ts`. Three semantics for one job means inconsistent error-eviction and more surface for cache bugs.
- **Proposal.** Standardize on `pMemoize` + `ExpiryMap` everywhere; replace `createTTLCache()` with `pMemoize(fn, { cache: new ExpiryMap(TTL) })`. Confirm error entries are still evicted (don't cache failed fetches).
- **Risks / trade-offs.** p-memoize's semantics differ subtly from the manual cache (keying, in-flight dedup, error handling); needs careful verification since this is on the hot render path.
- **Files.** `lib/notion.ts`, `lib/search-notion.ts`

### 4. Extract shared page-ID resolution logic
- **Impact:** 🟡 med · **Effort:** M · **Status:** ❌ rejected
- **Problem.** `lib/resolve-notion-page.ts` and `getNotionFallbackUrl()` in `pages/[pageId].tsx` duplicate the same resolution ordering (`pageUrlOverrides` → `pageUrlAdditions` → `canonicalPageMap`), with related logic also in `lib/map-page-url.ts`. Duplicated URL-resolution rules drift apart and are error-prone.
- **Proposal.** Extract one resolver used by both call sites; keep `map-page-url.ts` as the single source for canonical ID → URL.
- **Risks / trade-offs.** URL resolution is correctness-critical for static generation + fallback; the refactor must preserve every existing case (overrides, additions, unknown slugs).
- **Files.** `lib/resolve-notion-page.ts`, `pages/[pageId].tsx`, `lib/map-page-url.ts`

### 5. Drop unused HTTP client dependencies (`got`, `isomorphic-unfetch`)
- **Impact:** ⚪ low · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `package.json` declares `got`, `ky`, and `isomorphic-unfetch`, but only `ky` is imported in source (`lib/preview-images.ts`, `pages/api/social-image.tsx`, `components/wustep/ApplauseButton.tsx`). `got` and `isomorphic-unfetch` are dead install/security surface.
- **Proposal.** `pnpm remove got isomorphic-unfetch` after grepping to confirm no direct imports. Note `ky` as the single HTTP client in docs.
- **Risks / trade-offs.** Very low — a transitive dep might pull `got` itself, but that's unaffected by removing the top-level declaration.
- **Files.** `package.json`, `pnpm-lock.yaml`

### 6. Remove the `react-use` dependency (one hook in use)
- **Impact:** ⚪ low · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `react-use` (a large hook library) is pulled in for a single `useSearchParam` call in `components/NotionPage.tsx`.
- **Proposal.** Replace with Next.js `router.query` or a tiny local `useSearchParam` reading `URLSearchParams`, then remove `react-use`.
- **Risks / trade-offs.** Must match the hook's reactivity to URL changes; minor.
- **Files.** `components/NotionPage.tsx`, `package.json`

## UI/UX & Design

### 7. Unify focus-visible rings across the Lenses panel
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** Focus rings are defined at the frame level in `LensesPage.module.css`, but `.panel`/`.panelBody` interactive children (`.readingsLink`, `.quoteCiteLink`, `.relatedChip`) each declare ad-hoc focus outlines with differing offset/radius, and `.readingsLink:focus-visible` uses `currentColor` which can fall below contrast in dark mode. Inconsistent keyboard affordance on a core WCAG 2.2 AA surface.
- **Proposal.** Define one focus-ring token (e.g. `outline: 2px solid …; outline-offset: 3px`) applied to all panel interactive elements; remove the per-element rules. Verify contrast against the panel background in both themes.
- **Risks / trade-offs.** A single ring color must read against the full lens palette; use generous offset and test across lenses.
- **Files.** `components/wustep/lenses/LensesPage.module.css`

### 8. Audit lens card text contrast against WCAG AA
- **Impact:** 🔴 high · **Effort:** M · **Status:** ❌ rejected
- **Problem.** Cards set `--card-bg`/`--card-fg` per lens (`cards.tsx`, `registry.tsx`). Light-background lenses with small tagline text (`.cardHoverTagline` ~0.74rem) can land near or below the 4.5:1 AA threshold in light mode. The stated target is WCAG 2.2 AA.
- **Proposal.** Audit all lens colors against 4.5:1 for small text; nudge the failing backgrounds/text a few % in lightness (preferred over restyling). Add a documented `--card-min-contrast` convention and record the audit in a comment.
- **Risks / trade-offs.** Color tweaks shift the deck's aesthetic; keep adjustments small to preserve character per PRODUCT.md.
- **Files.** `components/wustep/lenses/registry.tsx`, `components/wustep/lenses/cards.tsx`, `components/wustep/lenses/LensesPage.module.css`

### 9. Add ARIA semantics + labels to the center dialog lens list
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** The center dialog is the primary lens-discovery surface, but `.dialogListItem` entries render without semantic list roles and the jump buttons need explicit per-lens labels so screen-reader/keyboard users can predict each control. No end-of-list cue either.
- **Proposal.** Ensure list semantics (`<ul>`/`<li>` or roles), add `aria-label="Jump to {title} lens"` per button, label the list ("All 32 lenses"), and add a subtle end-of-deck cue (IntersectionObserver on the last item).
- **Risks / trade-offs.** Verify against actual current markup — some labels may already exist in `CenterDialog.tsx`; scroll-triggered footer must be debounced.
- **Files.** `components/wustep/lenses/CenterDialog.tsx`, `components/wustep/lenses/LensesPage.module.css`

### 10. Fix panel scroll affordance on touch (`overscroll` + cue)
- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `.panelBody` uses `overflow-y: auto` with no `overscroll-behavior`, so on iOS a pull past the top bounces to the canvas behind (and can dismiss the panel). Long lenses give no visual cue that the body scrolls. Contrast with `.dialogList`, which already sets `overscroll-behavior: contain`.
- **Proposal.** Add `overscroll-behavior: contain` to `.panelBody`; add a bottom inset shadow (or `scrollbar-gutter: stable` where supported) to signal more content below.
- **Risks / trade-offs.** `scrollbar-gutter` support varies — inset-shadow fallback is safe.
- **Files.** `components/wustep/lenses/LensesPage.module.css`

### 11. Make the "play animations" button reachable on touch devices
- **Impact:** 🟡 med · **Effort:** S · **Status:** ❌ rejected
- **Problem.** `.playAnimationsButton` is revealed only on header hover via `@media (hover: hover)`. On touch devices the header never hovers, so the replay-entrance control is invisible and unreachable.
- **Proposal.** Under `(hover: none)`, keep the button persistently visible at an appropriate opacity with a ≥44px tap target; retain hover-reveal on desktop.
- **Risks / trade-offs.** Consumes header real estate on mobile — use a compact icon; ensure it doesn't crowd the theme toggle.
- **Files.** `components/wustep/lenses/LensesPage.module.css`, `components/wustep/lenses/LensesPage.tsx`

### 12. Add a loading/skeleton state for the Lenses canvas entrance
- **Impact:** 🟡 med · **Effort:** M · **Status:** ❌ rejected
- **Problem.** The canvas starts fully hidden (`opacity: 0`) and fades in via a staged entrance; on slow networks users see a blank frame for seconds with no feedback. The existing `Loading` component isn't used in this flow.
- **Proposal.** Render a minimal placeholder grid (same layout as real cards) behind the fade so the transition feels continuous; cross-fade to real cards; skip the stagger under `prefers-reduced-motion`.
- **Risks / trade-offs.** Skeleton grid must match the real grid exactly or the swap will jump; test across viewports.
- **Files.** `components/wustep/lenses/LensesPage.tsx`, `components/wustep/lenses/LensesPage.module.css`, `components/wustep/lenses/Canvas.tsx`

### 13. Give animated illustrations a clean resting frame under reduced-motion
- **Impact:** 🟡 med · **Effort:** M · **Status:** ❌ rejected
- **Problem.** Card SVG illustrations default to `animation-play-state: paused` and run on hover/select; under `prefers-reduced-motion` all animations disable globally, which can freeze an illustration mid-keyframe (e.g. mid-ripple), looking broken.
- **Proposal.** For reduced-motion, snap each animation to a deliberate resting keyframe (explicit transform/opacity reset) rather than wherever it happened to pause. Spot-check all lenses.
- **Risks / trade-offs.** Many keyframes to review; some may need a per-lens resting state.
- **Files.** `components/wustep/lenses/LensesPage.module.css`, `components/wustep/lenses/cards.tsx`

## DevEx

### 14. Add `pnpm build` (and typecheck) to CI
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `.github/workflows/build.yml` only runs `pnpm test` (lint + prettier). It never runs `pnpm build` or `pnpm typecheck`, so a change that passes lint but breaks the Next.js build or types is only caught on Vercel after merge. (The pre-push hook runs typecheck locally but CI doesn't.)
- **Proposal.** Add a `pnpm typecheck` step and a `pnpm build` step to the workflow. Cache `.next/` to keep it fast. Note that build runs `prebuild → notion:index`, which hits Notion — consider gating the index step or providing a cached index in CI.
- **Risks / trade-offs.** Build is slower and depends on Notion availability at CI time; may need a timeout/retry or a way to skip the live crawl.
- **Files.** `.github/workflows/build.yml`, `docs/development.md`

### 15. Introduce a real unit-test runner (Vitest) with starter tests
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** `package.json`'s `test` script only runs lint + prettier; `docs/development.md` confirms there's no unit suite. Pure logic in `lib/` (config normalization, canonical page IDs, URL mapping, `cn()`) has no regression net.
- **Proposal.** Add `vitest`, a `vitest.config.ts`, a `test:unit` script wired into `run-p`, and ~10–15 starter tests for pure `lib/` utilities. Document how to run tests in `docs/development.md`.
- **Risks / trade-offs.** ESM/jsdom setup can be fiddly; tests may surface latent type issues (net positive). Adds CI time.
- **Files.** `package.json`, `vitest.config.ts` (new), `lib/__tests__/*` (new), `docs/development.md`, `.github/workflows/build.yml`

### 16. Enforce TypeScript strictness and pay down `any`
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** `docs/development.md` states "no `any` allowed in new code," yet ~23 `any` usages exist in source (`lib/oembed.ts`, `lib/get-tweets.ts`, `lib/notion.ts`, `components/NotionPage.tsx`, others). Convention and reality have drifted.
- **Proposal.** Turn on stricter flags in `tsconfig.json` (e.g. `noUncheckedIndexedAccess`), then fix the `any` sites with proper `notion-types` types and `catch (err: unknown)` + guards. Do it incrementally so the build stays green.
- **Risks / trade-offs.** Some third-party types are incomplete (`notion-client`), so a few typed stubs or narrow casts may remain; may reveal latent bugs (a feature).
- **Files.** `tsconfig.json`, `lib/oembed.ts`, `lib/get-tweets.ts`, `lib/notion.ts`, `components/NotionPage.tsx`, and other flagged files, `docs/development.md`

### 17. Remove the duplicate legacy ESLint config
- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** Both `.eslintrc.json` (legacy) and `eslint.config.js` (flat) exist. ESLint 9 uses the flat config; the legacy file is redundant and tools may read one or the other unpredictably (e.g. `no-process-env` lives only in the legacy file).
- **Proposal.** Fold any rules unique to `.eslintrc.json` into `eslint.config.js`, delete `.eslintrc.json`, and confirm `pnpm test:lint` is unchanged.
- **Risks / trade-offs.** Low — verify no unique rule is silently dropped.
- **Files.** `eslint.config.js`, `.eslintrc.json` (delete), `docs/development.md`

### 18. Standardize className merging on `cn()` and ban `classnames`
- **Impact:** 🟡 med · **Effort:** M · **Status:** ✅ accepted
- **Problem.** ~11 components import `classnames` while `lib/utils.ts` exports a `cn()` helper (`clsx` + `tailwind-merge`) that's better for Tailwind class conflicts. Two patterns for one job, plus a redundant dependency.
- **Proposal.** Migrate all `classnames` usages to `cn()`, remove `classnames` from `package.json`, and add a `no-restricted-imports` ESLint rule so it can't creep back. Document the convention in `docs/development.md`.
- **Risks / trade-offs.** `tailwind-merge` changes conflict-resolution semantics vs `classnames`; spot-check each migrated component visually.
- **Files.** ~11 `components/**/*.tsx`, `lib/utils.ts`, `package.json`, `eslint.config.js`, `docs/development.md`
